# mcp-openproject

MCP-сервер к трекеру OpenProject: чтение тикетов, комментарии, вложения, списание
времени. Транспорт — stdio.

Общий порядок подключения MCP-серверов — в [`../README.md`](../README.md), правила
автоподтверждения инструментов — в [`docs/mcp-tools.md`](../../../docs/mcp-tools.md).

---

## Инструменты

| Инструмент | Когда |
| --- | --- |
| `get_work_package` | Прочитать тикет по ID: тип, статус, описание, `lockVersion` |
| `get_work_package_activities` | Комментарии тикета; `include_changes` добавляет историю изменений полей |
| `get_work_package_attachments` | Список вложений; `download: true` — скачать файлы и читать их обычным Read |
| `add_work_package_comment` | Опубликовать комментарий |
| `update_work_package` | Статус (по имени), тема, описание, процент готовности, исполнитель |
| `log_time` | Списать время |
| `search_work_packages` | Поиск по теме, статусу, типу, дате в проекте из `OPENPROJECT_PROJECT` |

## Установка

```bash
npm install --prefix tools/mcp-servers/mcp-openproject
```

## Конфигурация

| Переменная | Назначение |
| --- | --- |
| `OPENPROJECTTOKEN` | Personal Access Token: OpenProject → Account settings → Access tokens |
| `OPENPROJECT_URL` | Базовый адрес инсталляции |
| `OPENPROJECT_PROJECT` | Идентификатор проекта для поиска |
| `NODE_EXTRA_CA_CERTS` | Путь к CA-бандлу, если инсталляция за корпоративным CA |

Источники значений по приоритету: переменные процесса → `.env` рядом с сервером →
`.envrc` в корне репозитория. Третий шаг нужен потому, что `direnv` до MCP-процесса
не доходит: процесс запускает клиент, а не оболочка. Внутри `.envrc` переменная `$PWD`
раскрывается по каталогу самого файла — это удобно для пути к CA.

## Что стоит знать

- **`update_work_package` сам подтягивает `lockVersion`.** Без него сервер отвечает
  409: OpenProject использует оптимистичную блокировку и требует версию, которую
  клиент видел последней.
- **`get_work_package_attachments` с `download: true` пишет файлы на диск** и потому
  не автоподтверждается. Каталог создаётся с правами `0700`, файлы — `0600`, имена
  санитизируются (сервер может прислать `fileName` с путём в нём). **Файлы не
  удаляются автоматически** — чистить вручную, если в скриншотах чувствительные данные.
- **Корпоративный CA заменяет системные корни, а не дополняет их.** Одиночный
  сертификат в `NODE_EXTRA_CA_CERTS` рвёт цепочку до публичных сайтов
  (`unable to get issuer certificate`) — нужен полный бандл.

## Как приспособить к своему проекту

Сервер написан под REST API v3 OpenProject. Для Jira, YouTrack или GitLab Issues
переписывается слой HTTP-запросов в `index.js`; набор инструментов и их сигнатуры
переносятся без изменений — они описывают работу с тикетом вообще, а не с конкретным
трекером.

Что почти наверняка придётся поменять помимо адресов эндпоинтов:

1. **Модель версионирования.** `lockVersion` есть не везде; в Jira конфликт решается
   иначе, и `update_*` упростится.
2. **Способ смены статуса.** Здесь статус задаётся по имени, и сервер сам ищет его id
   в списке доступных переходов. В трекерах с жёстким workflow переход может быть
   недоступен из текущего состояния — это отдельная ветка обработки ошибки.
3. **Поиск.** `search_work_packages` строит фильтр в формате OpenProject; в Jira его
   место займёт JQL.
