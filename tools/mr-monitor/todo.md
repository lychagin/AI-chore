# MR Monitor — идеи на будущее

> Бэклог развития скрипта. Пока НЕ реализуем — только фиксируем, чтобы не забыть.

## Флаг `--ignore-comments`

**Идея:** управление поведением при неотвеченных комментариях в MR.

- **По умолчанию (без флага):** если в MR есть незакрытые/неотвеченные
  комментарии (неразрешённые дискуссии) — скрипт прекращает работу с понятной
  ошибкой. Если все комментарии отвечены/дискуссии разрешены — продолжает работу
  как задумано.
- **С флагом `--ignore-comments`:** неотвеченные комментарии игнорируются,
  скрипт продолжает работу.

**Привязка к текущей реализации:** уже сейчас диспетчер `decide_action`
останавливается на `detailed_merge_status == "discussions_not_resolved"`
(см. `_BLOCKER_STATUSES`). Поле `blocking_discussions_resolved` тоже есть в ответе
GET MR. Флаг `--ignore-comments` должен исключать `discussions_not_resolved` из
числа стоп-блокеров (а остальные блокеры — `not_approved`, `draft_status` —
оставить как есть).

## Follow-up из финального ревью (Minor)

- **Локальный rebase может перезаписать ветку пользователя.** `rebase_local`
  делает `git worktree add -B <source_branch> --force`, что сбрасывает локальную
  ветку `source_branch` на `origin/<source_branch>`. Если та ветка с
  незапушенными коммитами уже checked out в основном репо — коммиты теряются.
  Безопаснее: создавать worktree на отдельной ветке (`MR-monitoring-<iid>`) и
  пушить `HEAD:<source_branch>` через `--force-with-lease`, затем удалять эту
  ветку в cleanup.
- **`enable_auto_merge` шлёт булевы как строку `"true"`** (form-urlencoded) — не
  покрыто тестом проброс `sha`. Низкий риск, добавить тест при случае.
