# AI-chore

Набор агентов, скиллов, команд и утилит для Claude Code, собранный на реальном проекте
и очищенный от его специфики. Домен и стек заменены сквозным проектом-примером —
[OrderShop](examples/example-project.md); рядом с каждым нетривиальным артефактом лежит
README с разделом «как приспособить к своему проекту».

Ничего здесь не работает «из коробки под любой проект» — и не должно. Это заготовки,
у которых уже продумана форма: что агент читает, в каком порядке, что считается
доказательством, где он обязан остановиться и спросить. Содержимое подставляешь своё.

## Установка в проект

```bash
./install.sh --to /path/to/your-project            # интерактивно, показывает что положит
./install.sh --to /path/to/your-project --dry-run  # только показать
./install.sh --to /path/to/your-project --only skills,hooks
```

Скрипт раскладывает выбранное в `.claude/` целевого проекта и **не перезаписывает**
существующие файлы без `--force`. Утилиты из `tools/` не устанавливаются — их
копируют вручную туда, где они нужны, по README каждой утилиты.

## Порядок знакомства

2. [`hooks/README.md`](hooks/README.md) — самое дешёвое во внедрении и сразу заметное.
3. [`skills/README.md`](skills/README.md) — рабочие циклы; бери по одному, не пачкой.
4. [`agents/README.md`](agents/README.md) — рой, самое трудоёмкое в адаптации.

## Чего здесь нет

- Знаний о конкретном проекте: memory bank поставляется пустым, с описанием структуры.
- Готовых правил код-ревью: они у каждой команды свои и выводятся из накопленных
  ремарок — для этого есть [`/mine-patterns`](skills/mine-patterns/SKILL.md).
- Инструментов, которые нельзя оторвать от исходного стека. Там, где полезной была
  методика, а не код, она осталась текстом в README — например, набор зондов для
  разбора зависаний ночного прогона.
