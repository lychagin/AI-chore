# Агенты

Определения субагентов для Claude Code. Кладутся в `.claude/agents/` проекта, вызываются
через `Agent(subagent_type: "<имя>")` либо по описанию в поле `description`.

Конкретика в текстах — [проект-пример OrderShop](../examples/example-project.md).

---

## `tools/` — узкоспециализированные агенты

Пять из них различаются не предметной областью, а **способом рассуждения**. Это не
косметика: агент, которому предписан один режим, не сползает в остальные и возвращает
предсказуемую форму ответа.

| Агент | Режим | Когда звать |
| --- | --- | --- |
| [`code-searcher`](tools/code-searcher.md) | Chain of Draft — предельно сжатые символьные шаги | Найти, где лежит символ или логика; вернуть `file:line`, а не пересказ |
| [`code-thinker`](tools/code-thinker.md) | Chain of Thought — явные последовательные шаги | Разбор причины бага, выбор между вариантами архитектуры |
| [`code-executor`](tools/code-executor.md) | Chain of Code — план, код, запуск, результат | Проверить гипотезу запуском, а не рассуждением |
| [`code-knowledge`](tools/code-knowledge.md) | Chain of Knowledge — подтягивание внешнего знания на каждом шаге | Сверка со стандартом, сравнение подходов |
| [`code-verifier`](tools/code-verifier.md) | Chain of Verification — сам задаёт себе проверочные вопросы и правит вывод | Перепроверить готовый вывод перед тем, как на него опереться |

| Агент | Когда звать |
| --- | --- |
| [`code-architecture-reviewer`](tools/code-architecture-reviewer.md) | Ревью свежего кода на соответствие принятым в проекте решениям и на встраиваемость в систему |
| [`tech-writer`](tools/tech-writer.md) | Техдокументация из ADR, комментариев `@agent-doc` и спецификации API |
| [`memory-bank-synchronizer`](tools/memory-bank-synchronizer.md) | Привести memory bank в соответствие с кодом, когда код ушёл вперёд документации |
| [`ux-design-expert`](tools/ux-design-expert.md) | UX-разбор: подхватывает уже принятые в проекте конвенции вместо навязывания своих |
| [`get-current-datetime`](tools/get-current-datetime.md) | Текущее время: модель его не знает, а датировать документы надо |

## `memory-bank/` — работа с требованиями и контекстом

| Агент | Что делает |
| --- | --- |
| [`decompose-agent`](memory-bank/decompose-agent.md) | Разбирает документ требований на сущности, требования и черновики юз кейсов |
| [`use-case-extractor-agent`](memory-bank/use-case-extractor-agent.md) | Полный разбор до готовых юз кейсов: акторы, предусловия, основной/альтернативные/исключительные сценарии, бизнес-правила, матрица трассируемости |
| [`context-query-agent`](memory-bank/context-query-agent.md) | Собирает узкий срез memory bank под конкретный вопрос вместо загрузки всего |
| [`context-diff-agent`](memory-bank/context-diff-agent.md) | Обрабатывает только дельту с прошлой синхронизации, а не весь репозиторий |
| [`stale-context-agent`](memory-bank/stale-context-agent.md) | Находит записи, противоречащие текущему коду |

Вызываются в том числе командами из [`../commands/`](../commands/README.md).

## Как приспособить к своему проекту

**Агенты из `tools/` переносятся как есть** — они рассуждают о коде вообще и не знают
про твой стек. Единственное, что стоит проверить, — список инструментов в frontmatter:
если у тебя нет какого-то MCP-сервера, агент упадёт на первом же вызове.

**Агенты из `memory-bank/` требуют настройки в трёх местах:**

1. **Раскладка артефактов.** Ожидается `.claude/entities/`, `.claude/requirements/`,
   `.claude/analysis/`. Меняется в разделе «Входные данные» каждого агента.
2. **Формат исходного документа.** `use-case-extractor-agent` писался под документ
   функциональных требований с нумерацией пунктов. Разделы «Признаки юз кейса» и
   «Определение границ» — это и есть привязка к формату; если у тебя пользовательские
   истории или план работ, переписывать надо именно их.
3. **Домен в примерах.** Внутри есть развёрнутый сквозной пример (приём и обработка
   заявки оператором и модератором) — он оставлен намеренно: агент по нему понимает
   требуемую степень детализации. Домен подменён на OrderShop; заменяй на свой, когда
   он у тебя устоится, но **не удаляй пример целиком** — без него агент выдаёт
   поверхностные сценарии в три шага.

## Ещё не перенесено

**Ролевой конвейер** — `team-leader`, `analyst`, `architect`, `coder`, `tester`,
`reviewer`, `troubleshooter`, `final-reviewer` — и команда `/swarm`, которая их
запускает. Это самая объёмная часть: в исходных промптах конкретный стек вшит в тело
инструкций, и перенос означает переписывание, а не чистку. Появится отдельным заходом,
вместе с `agents/roles/` и разделом о том, как перестроить цепочку под свой процесс.
