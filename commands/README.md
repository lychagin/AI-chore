# Команды

Слэш-команды Claude Code. Кладутся в `.claude/commands/` проекта и вызываются как
`/decompose`, `/mr` и т. д.

Конкретика в текстах — [проект-пример OrderShop](../examples/example-project.md).

---

## Рой агентов

| Команда | Что делает |
| --- | --- |
| [`/swarm`](swarm.md) | Поднимает инфраструктуру обмена сообщениями, запускает watchdog и отдаёт управление `team-leader`, который проводит UC через весь цикл: анализ → ADR → тесты → реализация → ревью → документация |

Состав ролей и порядок адаптации — [`agents/README.md`](../agents/README.md).

## Работа с требованиями

| Команда | Что делает |
| --- | --- |
| [`/decompose`](decompose.md) | Разбирает документ требований на структурированные артефакты: сущности, требования, черновики юз кейсов, отчёт декомпозиции с матрицей трассируемости |
| [`/new-requirement`](new-requirement.md) | Заводит новое требование по шаблону, продолжая сквозную нумерацию |
| [`/new-usecase`](new-usecase.md) | Заводит новый юз кейс по шаблону: акторы, предусловия, основной и альтернативные сценарии |
| [`/generate-diagrams`](generate-diagrams.md) | Строит диаграммы по накопленным сущностям и юз кейсам |

Шаблоны документов, на которые они опираются, — в [`../docs/templates/`](../docs/templates/).
Тяжёлую часть разбора выполняют агенты из [`../agents/memory-bank/`](../agents/README.md).

## Работа с MR

| Команда | Что делает |
| --- | --- |
| [`/mr`](mr.md) | Собирает описание MR по адаптивному шаблону (состав секций зависит от того, что реально в diff'е) и по желанию создаёт MR |

Опирается на утилиту [`tools/mr-template`](../tools/), которая считает контекст ветки
и тянет данные тикета. Без неё команда работать не будет.

## Как приспособить к своему проекту

1. **Пути к артефактам.** Команды ожидают раскладку `.claude/entities/`,
   `.claude/requirements/`, `.claude/analysis/`. Если у тебя требования лежат иначе —
   правится в одном месте вверху каждой команды.
2. **Нумерация.** `UC-001`, `REQ-F-002` — это конвенция, а не требование. Меняется
   вместе с шаблонами в `docs/templates/`.
3. **Формат исходных требований.** `/decompose` писался под документ функциональных
   требований со сплошной нумерацией пунктов. Если у тебя вместо ФТ план работ или
   набор пользовательских историй — переписывать придётся именно признаки, по которым
   агент находит границы сценария; остальной конвейер сохраняется.
4. **`/mr`** завязана на GitLab и на внешнюю утилиту. Под GitHub меняется способ
   создания MR и получения diffstat, шаблон описания остаётся.

## Требования к окружению

`/swarm` полагается на `python3` в системе (watchdog разбирает heartbeat-файлы) и на
переменные `SWARM_MODULE` / `SWARM_MODULE_DIR` в `.envrc`. `/mr` требует утилиты
[`tools/mr-template`](../tools/). Остальные команды внешних зависимостей не имеют.
